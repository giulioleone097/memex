## Real defect found and fixed (in scope, not a workaround)

Real dogfooding of `graph build` against **this repository** (required by T9.1) immediately surfaced that only 24 files / 793 nodes were scanned — `plugins/memex/**` (the plugin's own source) was entirely missing. Root cause: `graph-store.ts`'s `excluded()` filter dropped ANY path segment literally named `memex`/`.memex`, intended only to skip the wiki's own generated content directory (always `<root>/memex`, per `paths.ts`). Post-rename, the plugin's own path `plugins/memex/` collided with that filter and was silently blackholed from every graph/search/ask/impact/report operation run on this repo — with zero diagnostic.

Fixed with TDD (regression test written and confirmed red, then fix, then green): split the exclusion list into anywhere-excluded build/dependency dirs vs. root-only-excluded wiki-content dirs. Added `tests/integration/graph-repository.test.mjs` test proving a nested `plugins/memex/src/index.ts` is now scanned while the top-level wiki `memex/` directory stays excluded. Full gate re-run after the fix: build/typecheck/lint clean, all 308 tests pass, 0 regressions. Real impact: `graph build` went from 24 files/793 nodes/929 edges to **172 files/5,997 nodes/8,433 edges**; `graph query --query dispatchGraph` now correctly resolves to `plugins/memex/src/adapter.ts:282`.
